# 澄聘：企业级交付路线

当前定位：招聘流程原型。大型金融机构的采购评估需要安全、隐私、可靠性和模型治理的可验证证据；仅有简历评分页面远远不够。

## 真实招聘流程

1. **编制与审批**：部门提出 HC，财务与 HRBP 批准，再发布岗位。岗位要求需留版本，区分必需、加分、可培养能力。
2. **候选人进入人才库**：记录来源、投递时间、岗位、授权/告知、文件版本、重复候选人；允许人工修正解析结果。
3. **初筛**：先应用可解释、岗位相关的硬条件；再给出辅助排序。每条结论需定位到简历原文和岗位条款。缺证据时显示“待核实”，不自动淘汰。
4. **一面/二面/终面**：每轮有面试官、约定时间、统一评分卡、事实笔记、待追问问题、独立提交与汇总决策；记录状态变更历史。
5. **决定与沟通**：用人经理和 HR 审核，记录人工决定及理由，发送邀请或拒绝通知，支持候选人信息更正与申诉。
6. **留存与删除**：按招聘地区和公司政策设置保留期限，处理撤回授权、导出与删除请求。

## P0：真实数据进入系统之前

| 能力 | 最低验收证据 |
|---|---|
| 登录和权限 | SSO、岗位级 RBAC，未经授权不能读取其他岗位简历；自动化越权测试通过 |
| 数据保护 | HTTPS、数据库和文件加密、密钥轮换、备份恢复演练 |
| 候选人隐私 | 告知与授权记录、保留期限、删除/导出流程；模型供应商数据处理协议 |
| 审计 | 读取、导出、筛选、评分、状态变更均记录操作者、时间、对象、前后值；日志防篡改 |
| 文件安全 | 文件类型内容检测、恶意文件扫描、大小与页数限制、隔离解析 |
| 模型治理 | 模型/提示词/岗位标准版本、评分重现、人工复核、误判统计、偏差评估 |
| 运行保障 | 数据库迁移、异步队列、限流、超时与重试、监控告警、灾备目标 |

## P1：招聘团队可用

- 批量导入、查重、可编辑的解析结果与原文定位。
- 候选人状态看板、面试日程、面试官任务与反馈催办。
- 可配置评分卡、面试官独立评分、分歧汇总、录用审批。
- 按岗位和来源查看漏斗、阶段耗时、反馈完成率；导出需权限控制。
- 中英文界面、键盘与屏幕阅读器支持、移动端适配。

## P2：跨系统集成

- 与企业既有 ATS、HRIS、邮箱、日历和身份提供商对接。
- Webhook 与 API 幂等、导入/导出格式、失败重放和同步对账。
- 多组织隔离、地区化数据驻留及政策配置。

## 当前实现的限制

- 接口没有身份认证；仅适合本机用虚构数据演示。
- SQLite 和同步逐份模型调用不适合大批量或并发招聘。
- 评分是模型建议，未完成准确率、稳定性与公平性验证。
- 目前只有中文界面；README 有英文摘要，不能称为双语产品。
- 截图和演示尚需按真实运行界面重新制作；不要用虚构数据宣称业务效果。
